SQLITE_BUSY

busy

다른 표기: 5

어떤 문제인가요?

다른 데이터베이스 연결의 동시 작업 때문에 SQLite 작업을 진행하지 못한 경우입니다.

번역 설명

SQLITE_BUSY 결과 코드는 다른 데이터베이스 연결(일반적으로 별도 프로세스의 데이터베이스 연결)에 의한 동시 활동으로 인해 데이터베이스 파일을 쓸 수 없음(또는 경우에 따라 읽을 수 없음)을 나타냅니다. 예를 들어, 프로세스 A가 대규모 쓰기 트랜잭션 중에 있고 동시에 프로세스 B가 새로운 쓰기 트랜잭션을 시작하려고 시도하는 경우 SQLite는 한 번에 하나의 기록기만 지원하기 때문에 프로세스 B는 SQLITE_BUSY 결과를 반환합니다. 프로세스 B는 새 트랜잭션을 시작하기 전에 프로세스 A가 트랜잭션을 완료할 때까지 기다려야 합니다. sqlite3_busy_timeout() 및 sqlite3_busy_handler() 인터페이스와 busy_timeout pragma는 B를 처리하여 SQLITE_BUSY 오류를 처리하는 데 사용할 수 있습니다. SQLITE_BUSY 오류는 트랜잭션이 처음 시작될 때, 쓰기 또는 업데이트 작업 중, 트랜잭션이 커밋될 때 등 트랜잭션의 어느 시점에서나 발생할 수 있습니다. 트랜잭션 도중에 SQLITE_BUSY 오류가 발생하는 것을 방지하기 위해 애플리케이션은 BEGIN 대신 BEGIN IMMEDIATE를 사용하여 트랜잭션을 시작할 수 있습니다. BEGIN IMMEDIATE 명령은 자체적으로 SQLITE_BUSY를 반환할 수 있지만 성공하면 SQLite는 다음 COMMIT를 통해 동일한 데이터베이스에 대한 후속 작업이 SQLITE_BUSY를 반환하지 않도록 보장합니다. SQLITE_BUSY_RECOVERY 및 SQLITE_BUSY_SNAPSHOT도 참조하세요. SQLITE_BUSY 결과 코드는 SQLITE_LOCKED와 다릅니다. SQLITE_BUSY는 아마도 별도의 프로세스에서 별도의 데이터베이스 연결과의 충돌을 나타내는 반면, SQLITE_LOCKED는 동일한 데이터베이스 연결(또는 때로는 공유 캐시를 사용한 데이터베이스 연결) 내 충돌을 나타냅니다.

공식 설명 · 원문

The SQLITE_BUSY result code indicates that the database file could not be written (or in some cases read) because of concurrent activity by some other database connection, usually a database connection in a separate process. For example, if process A is in the middle of a large write transaction and at the same time process B attempts to start a new write transaction, process B will get back an SQLITE_BUSY result because SQLite only supports one writer at a time. Process B will need to wait for process A to finish its transaction before starting a new transaction. The sqlite3_busy_timeout() and sqlite3_busy_handler() interfaces and the busy_timeout pragma are available to process B to help it deal with SQLITE_BUSY errors. An SQLITE_BUSY error can occur at any point in a transaction: when the transaction is first started, during any write or update operations, or when the transaction commits. To avoid encountering SQLITE_BUSY errors in the middle of a transaction, the application can use BEGIN IMMEDIATE instead of just BEGIN to start a transaction. The BEGIN IMMEDIATE command might itself return SQLITE_BUSY, but if it succeeds, then SQLite guarantees that no subsequent operations on the same database through the next COMMIT will return SQLITE_BUSY. See also: SQLITE_BUSY_RECOVERY and SQLITE_BUSY_SNAPSHOT. The SQLITE_BUSY result code differs from SQLITE_LOCKED in that SQLITE_BUSY indicates a conflict with a separate database connection, probably in a separate process, whereas SQLITE_LOCKED indicates a conflict within the same database connection (or sometimes a database connection with a shared cache).
