ExceptionGroup

ExceptionGroup

어떤 문제인가요?

여러 Exception을 묶어 보고한 예외 그룹입니다.

번역 설명

이 두 예외 유형 모두 예외를 시퀀스 예외로 래핑합니다. msg 매개변수는 문자열이어야 합니다. 두 클래스의 차이점은 BaseExceptionGroup은 BaseException을 확장하고 모든 예외를 래핑할 수 있는 반면 ExceptionGroup은 Exception을 확장하며 Exception의 하위 클래스만 래핑할 수 있다는 것입니다. 이 디자인은 Exception을 제외하면 ExceptionGroup을 포착하지만 BaseExceptionGroup은 포착하지 않도록 하기 위한 것입니다. BaseExceptionGroup 생성자는 포함된 모든 예외가 예외 인스턴스인 경우 BaseExceptionGroup이 아닌 ExceptionGroup을 반환하므로 선택을 자동으로 만드는 데 사용할 수 있습니다. 반면에 ExceptionGroup 생성자는 포함된 예외가 Exception 하위 클래스가 아닌 경우 TypeError를 발생시킵니다. 예외 그룹은 포함된 예외 유형에 대해 일반적입니다. BaseExceptionGroup은 __new__()를 정의하므로 다른 생성자 서명이 필요한 하위 클래스는 __init__() 대신 이를 재정의해야 합니다. 예를 들어, 다음은exit_code를 받아들이고 그로부터 그룹의 메시지를 구성하는 예외 그룹 하위 클래스를 정의합니다. ExceptionGroup과 마찬가지로 Exception의 하위 클래스이기도 한 BaseExceptionGroup의 하위 클래스는 Exception의 인스턴스만 래핑할 수 있습니다.

공식 설명 · 원문

Both of these exception types wrap the exceptions in the sequence excs. The msg parameter must be a string. The difference between the two classes is that BaseExceptionGroup extends BaseException and it can wrap any exception, while ExceptionGroup extends Exception and it can only wrap subclasses of Exception. This design is so that except Exception catches an ExceptionGroup but not BaseExceptionGroup. The BaseExceptionGroup constructor returns an ExceptionGroup rather than a BaseExceptionGroup if all contained exceptions are Exception instances, so it can be used to make the selection automatic. The ExceptionGroup constructor, on the other hand, raises a TypeError if any contained exception is not an Exception subclass. Exception groups are generic over the type of their contained exceptions. Note that BaseExceptionGroup defines __new__(), so subclasses that need a different constructor signature need to override that rather than __init__(). Like ExceptionGroup, any subclass of BaseExceptionGroup which is also a subclass of Exception can only wrap instances of Exception.
