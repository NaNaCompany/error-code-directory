  • ExceptionGroup
    ExceptionGroup

    Beide Ausnahmetypen umschließen die Ausnahmen in der Sequenz excs. Der msg-Parameter muss eine Zeichenfolge sein. Der Unterschied zwischen den beiden Klassen besteht darin, dass BaseExceptionGroup BaseException erweitert und jede Ausnahme umschließen kann, während ExceptionGroup Exception erweitert und nur Unterklassen von Exception umschließen kann. Dieses Design ist so konzipiert, dass außer Exception eine ExceptionGroup abfängt, nicht jedoch BaseExceptionGroup. Der BaseExceptionGroup-Konstruktor gibt eine ExceptionGroup statt einer BaseExceptionGroup zurück, wenn alle enthaltenen Ausnahmen Ausnahmeinstanzen sind, sodass er verwendet werden kann, um die Auswahl automatisch vorzunehmen. Der ExceptionGroup-Konstruktor hingegen löst einen TypeError aus, wenn eine enthaltene Ausnahme keine Exception-Unterklasse ist. Ausnahmegruppen sind hinsichtlich des Typs ihrer enthaltenen Ausnahmen generisch. Beachten Sie, dass BaseExceptionGroup __new__() definiert. Daher müssen Unterklassen, die eine andere Konstruktorsignatur benötigen, diese überschreiben und nicht __init__(). Im Folgenden wird beispielsweise eine Unterklasse einer Ausnahmegruppe definiert, die einen Exit_code akzeptiert und daraus die Nachricht der Gruppe erstellt. Wie ExceptionGroup kann jede Unterklasse von BaseExceptionGroup, die auch eine Unterklasse von Exception ist, nur Instanzen von Exception umschließen.

    PythonPython

    MemoryError

    Wird ausgelöst, wenn für einen Vorgang nicht mehr genügend Arbeitsspeicher vorhanden ist, die Situation aber dennoch gerettet werden kann (durch Löschen einiger Objekte). Der zugehörige Wert ist eine Zeichenfolge, die angibt, welche Art von (internem) Vorgang nicht über genügend Speicher verfügt. Beachten Sie, dass der Interpreter aufgrund der zugrunde liegenden Speicherverwaltungsarchitektur (malloc()-Funktion von C) möglicherweise nicht immer in der Lage ist, diese Situation vollständig zu beheben. Es wird dennoch eine Ausnahme ausgelöst, sodass ein Stack-Traceback gedruckt werden kann, falls ein außer Kontrolle geratenes Programm die Ursache war.

  • OSErrorEnvironmentError · IOError
    OSError

    Diese Ausnahme wird ausgelöst, wenn eine Systemfunktion einen systembezogenen Fehler zurückgibt, einschließlich E/A-Fehlern wie „Datei nicht gefunden“ oder „Datenträger voll“ (nicht für ungültige Argumenttypen oder andere zufällige Fehler). Die zweite Form des Konstruktors legt die entsprechenden Attribute fest, wie unten beschrieben. Wenn nicht angegeben, sind die Attribute standardmäßig „None“. Wenn drei Argumente übergeben werden, enthält das args-Attribut aus Gründen der Abwärtskompatibilität nur ein 2-Tupel der ersten beiden Konstruktorargumente. Der Konstruktor gibt häufig tatsächlich eine Unterklasse von OSError zurück, wie unten in den Betriebssystemausnahmen beschrieben. Die jeweilige Unterklasse hängt vom endgültigen Fehlernummerwert ab. Dieses Verhalten tritt nur auf, wenn OSError direkt oder über einen Alias ​​erstellt wird, und wird bei der Unterklassenerstellung nicht vererbt.

    PythonPython
  • OverflowError
    OverflowError

    Wird ausgelöst, wenn das Ergebnis einer arithmetischen Operation zu groß ist, um dargestellt zu werden. Dies kann bei Ganzzahlen nicht der Fall sein (die eher MemoryError auslösen als aufgeben würden). Aus historischen Gründen wird OverflowError jedoch manchmal für Ganzzahlen ausgelöst, die außerhalb eines erforderlichen Bereichs liegen. Aufgrund der fehlenden Standardisierung der Gleitkomma-Ausnahmebehandlung in C werden die meisten Gleitkomma-Operationen nicht überprüft.
