  • FAILED_PRECONDITION9 · google.rpc.Code.FAILED_PRECONDITION
    FAILED PRECONDITION

    La operación fue rechazada porque el sistema no se encuentra en el estado requerido para la ejecución de la operación. Por ejemplo, el directorio que se va a eliminar no está vacío, se aplica una operación rmdir a un directorio que no es, etc. Los implementadores del servicio pueden usar las siguientes pautas para decidir entre `FAILED_PRECONDITION`, `ABORTED` y `UNAVAILABLE`: (a) Utilice `UNAVAILABLE` si el cliente puede reintentar solo la llamada fallida. (b) Utilice "ABORTED" si el cliente debe volver a intentarlo en un nivel superior. Por ejemplo, cuando falla una prueba y configuración especificada por el cliente, indica que el cliente debe reiniciar una secuencia de lectura, modificación y escritura. (c) Utilice `FAILED_PRECONDITION` si el cliente no debe volver a intentarlo hasta que el estado del sistema se haya solucionado explícitamente. Por ejemplo, si un "rmdir" falla porque el directorio no está vacío, se debe devolver `FAILED_PRECONDITION` ya que el cliente no debe volver a intentarlo a menos que los archivos se eliminen del directorio.   • OUT_OF_RANGE11 · google.rpc.Code.OUT_OF_RANGE
    OUT OF RANGE

    La operación se intentó más allá del rango válido. Por ejemplo, buscar o leer más allá del final del archivo. A diferencia de `INVALID_ARGUMENT`, este error indica un problema que puede solucionarse si cambia el estado del sistema. Por ejemplo, un sistema de archivos de 32 bits generará `INVALID_ARGUMENT` si se le solicita leer en un desplazamiento que no está en el rango [0,2^32-1], pero generará `OUT_OF_RANGE` si se le solicita leer desde un desplazamiento posterior al tamaño del archivo actual. Existe bastante superposición entre "FAILED_PRECONDITION" y "OUT_OF_RANGE". Recomendamos usar `OUT_OF_RANGE` (el error más específico) cuando se aplique para que las personas que llaman y están iterando a través de un espacio puedan buscar fácilmente un error `OUT_OF_RANGE` para detectar cuando hayan terminado.
