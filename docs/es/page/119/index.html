  • SQLITE_BUSY5
    busy

    El código de resultado SQLITE_BUSY indica que el archivo de base de datos no se pudo escribir (o en algunos casos leer) debido a la actividad simultánea de alguna otra conexión de base de datos, generalmente una conexión de base de datos en un proceso separado. Por ejemplo, si el proceso A está en medio de una transacción de escritura grande y al mismo tiempo el proceso B intenta iniciar una nueva transacción de escritura, el proceso B obtendrá un resultado SQLITE_BUSY porque SQLite solo admite un escritor a la vez. El proceso B deberá esperar a que el proceso A finalice su transacción antes de comenzar una nueva transacción. Las interfaces sqlite3_busy_timeout() y sqlite3_busy_handler() y el pragma ocupado_timeout están disponibles para procesar B para ayudarlo a lidiar con los errores SQLITE_BUSY. Un error SQLITE_BUSY puede ocurrir en cualquier punto de una transacción: cuando la transacción se inicia por primera vez, durante cualquier operación de escritura o actualización, o cuando se confirma la transacción. Para evitar encontrar errores SQLITE_BUSY en medio de una transacción, la aplicación puede usar BEGIN IMMEDIATE en lugar de simplemente BEGIN para iniciar una transacción. El comando BEGIN IMMEDIATE podría devolver SQLITE_BUSY, pero si tiene éxito, SQLite garantiza que ninguna operación posterior en la misma base de datos hasta el siguiente COMMIT devolverá SQLITE_BUSY. Ver también: SQLITE_BUSY_RECOVERY y SQLITE_BUSY_SNAPSHOT. El código de resultado SQLITE_BUSY difiere de SQLITE_LOCKED en que SQLITE_BUSY indica un conflicto con una conexión de base de datos separada, probablemente en un proceso separado, mientras que SQLITE_LOCKED indica un conflicto dentro de la misma conexión de base de datos (o, a veces, una conexión de base de datos con un caché compartido).
