  • FAILED_PRECONDITION9 · google.rpc.Code.FAILED_PRECONDITION
    FAILED PRECONDITION

    A operação foi rejeitada porque o sistema não está num estado requerido para a execução da operação. Por exemplo, o diretório a ser apagado é não vazio, uma operação rmdir é aplicada a um não-diretório, etc. Os implementadores de serviços podem usar as seguintes diretrizes para decidir entre `FAILED_PRECONDITION`, `ABORTED' e `UNAVAILABLE`: (a) Use `UNAVAILABLE' se o cliente pode tentar apenas a chamada falhada. (b) Use `ABORTED' se o cliente deve tentar novamente a um nível superior. Por exemplo, quando um teste e conjunto especificado pelo cliente falha, indicando que o cliente deve reiniciar uma sequência de leitura-modify-write. (c) Use `FAILED_PRECONDITION` se o cliente não deve voltar a tentar. Tentar até que o estado do sistema tenha sido explicitamente corrigido. Por exemplo, se um "rmdir" falhar porque o diretório não está vazio, `FAILED_PRECONDITION' deve ser devolvido, uma vez que o cliente não deve tentar novamente a menos que os arquivos sejam excluídos do diretório.

  • OUT_OF_RANGE11 · google.rpc.Code.OUT_OF_RANGE
    OUT OF RANGE

    A operação foi tentada além do intervalo válido. Por exemplo, procurar ou ler passado fim de arquivo. Ao contrário de `INVALID_ARGUMENT`, este erro indica um problema que pode ser corrigido se o estado do sistema mudar. Por exemplo, um sistema de arquivos de 32 bits irá gerar `INVALID_ARGUMENT` se pedir para ler em um desvio que não está no intervalo [0,2^32-1], mas irá gerar `OUT_OF_RANGE` se pedir para ler a partir de um desvio passado do tamanho do arquivo atual. Há um pouco de sobreposição entre `FAILED_PRECONDITION` e `OUT_OF_RANGE`. Recomendamos usar `OUT_OF_RANGE` (o erro mais específico) quando se aplica de modo que os chamados que estão iterando através de um espaço podem facilmente usar `OUT_OF_RANGE`. Procurar um erro `OUT_OF_RANGE` para detectar quando eles estiverem feitos. HTTP Mapping: 400 Bad Request
