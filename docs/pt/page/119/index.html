  • SQLITE_BUSY5
    busy

    O código de resultado SQLITE_BUSY indica que o arquivo de base de dados não pôde ser escrito (ou, em alguns casos, lido) por causa da atividade concorrente por alguma outra conexão de base de dados, normalmente uma conexão de base de dados em um processo separado. Por exemplo, se o processo A estiver no meio de uma grande transação de escrita e ao mesmo tempo o processo B tentará iniciar uma nova transação de gravação, o processo B recuperará um resultado SQLITE_BUSY porque o SQLite só suporta um escritor de cada vez. O processo B precisará esperar pelo processo A para terminar a sua transação antes de iniciar uma nova transação. As interfaces sqlite3_busy_timeout() e sqlite3_busy_handler() e o pragma ocupado_timeout estão disponíveis para o processo B para ajudá-lo a lidar com erros SQLITE_BUSY. Um erro SQLITE_BUSY pode ocorrer em qualquer ponto em qualquer momento. uma transação: quando a transação é iniciada pela primeira vez, durante qualquer operação de gravação ou atualização, ou quando a transação se compromete. Para evitar encontrar erros SQLITE_BUSY no meio de uma transação, o aplicativo pode usar BEGIN IMMEDIATE em vez de apenas BEGIN para iniciar uma transação. O comando BEGIN IMMEDIATE pode ser ele próprio a devolver SQLITE_BUSY, mas se tiver sucesso, então SQLite garante que nenhuma operação subsequente no mesmo banco de dados através do próximo COMMIT irá devolver SQLITE_BUSY. Veja também: SQLITE_BUSY_RECOVERY e SQLITE_BUSY_SNAPSHOT. O código de resultado SQLITE_BUSY difere de SQLITE_LOCKED nesse SQLITE_BUSY indica um conflito com uma conexão de banco de dados separada, provavelmente num processo separado, enquanto SQLITE_L O BOCKED indica um conflito dentro da mesma conexão de banco de dados (ou às vezes uma conexão de banco de dados com um cache compartilhado).
