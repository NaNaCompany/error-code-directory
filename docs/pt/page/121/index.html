  • SQLITE_MISMATCH20
    mismatch

    O código de erro SQLITE_MISMAtch indica um erro do tipo de dados. SQLite é normalmente muito indulgente quanto às divergências entre o tipo de um valor e o tipo declarado do recipiente em que esse valor deve ser armazenado. Por exemplo, SQLite permite que a aplicação guarde um BLOB grande em uma coluna com um tipo declarado de BOOLEAN. Mas em alguns casos, SQLite é rigoroso quanto aos tipos. O erro SQLITE_MISMAtch é devolvido nesses poucos casos quando os tipos não coincidem. O roeid de uma tabela deve ser um inteiro. Tentar definir o roeid para qualquer outra coisa que não um inteiro (ou um NULL que será convertido automaticamente para o próximo inteiro disponível) resulta num erro SQLITE_MISMAtch.

  • SQLITE_MISUSE21
    misuse

    O código de retorno SQLITE_MISUSE pode ser devolvido se o aplicativo usar qualquer interface SQLite de uma forma indefinida ou não suportada. Por exemplo, usando uma declaração preparada após que essa declaração preparada tenha sido finalizada pode resultar em um erro SQLITE_MISUSE. SQLite tenta detectar o uso indevido e reportar o uso indevido usando este código de resultado. No entanto, não há garantia de que a detecção de uso indevido será bem sucedida. A detecção de erros é probabilística. As aplicações nunca devem depender de um valor de retorno SQLITE_MISUSE. Se o SQLite devolve alguma vez o SQLITE_MISUSE a partir de qualquer interface, isso significa que o aplicativo está codificado incorretamente e precisa ser corrigido. Não envie um aplicativo que às vezes retorna o SQLITE_MISUSE a partir de uma interface SQLite padrão, porque o aplicativo contém erros potencialmente graves.

  • SQLITE_PROTOCOL15
    protocol

    O código de resultado SQLITE_PROTOCOL indica um problema com o protocolo de bloqueio de arquivos utilizado pelo SQLite. O erro SQLITE_PROTOCOL só é devolvido atualmente quando se usa o modo WAL e se tenta iniciar uma nova transação. Existe uma condição de corrida que pode ocorrer quando duas conexões separadas de banco de dados tentam iniciar uma transação ao mesmo tempo no modo WAL. O perdedor da corrida recua e tenta novamente, após um breve atraso. Se a mesma conexão perder a corrida de bloqueio dezenas de vezes ao longo de um intervalo de vários segundos, irá eventualmente desistir e devolver SQLITE_PROTOCOL. O erro SQLITE_PROTOCOL deve aparecer na prática muito, muito raramente, e apenas quando há muitos processos separados que competem intensamente para escrever no mesmo banco de dados.
