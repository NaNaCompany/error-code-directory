  • SQLITE_BUSY5
    busy

    Le code de résultat SQLITE_BUSY indique que le fichier de base de données n'a pas pu être écrit (ou dans certains cas lu) en raison de l'activité concurrente d'une autre connexion de base de données, habituellement une connexion de base de données dans un processus séparé. Par exemple, si le processus A est au milieu d'une transaction d'écriture importante et en même temps que le processus B tente de démarrer une nouvelle transaction d'écriture, le processus B récupérera un résultat SQLITE_BUSY parce que SQLite ne supporte qu'un auteur à la fois. Le processus B devra attendre que le processus A termine sa transaction avant de commencer une nouvelle transaction. Les interfaces sqlite3_busy_timeout() et sqlite3_busy_handler() et le pragma bloody_timeout sont disponibles pour traiter B pour l'aider à traiter les erreurs SQLITE_BUSY. Une erreur SQLITE_BUSY peut se produire à n'importe quel moment dans le cas. une transaction : lorsque la transaction est commencée, pendant toute opération d'écriture ou de mise à jour, ou lorsque la transaction est engagée. Pour éviter de rencontrer des erreurs SQLITE_BUSY au milieu d'une transaction, l'application peut utiliser BEGIN IMMEDIATE au lieu de seulement BEGIN pour démarrer une transaction. La commande BEGIN IMMEDIATE pourrait lui-même retourner SQLITE_BUSY, mais s'il réussit, SQLite garantit qu'aucune opération ultérieure sur la même base de données par le biais de la prochaine COMMIT ne retournera SQLITE_BUSY. Voir aussi : SQLITE_BUSY_RECOVERY et SQLITE_BUSY_SNAPSHOT. Le code de résultat SQLITE_BUSY diffère de SQLITE_LOCKED dans lequel SQLITE_BUSY indique un conflit avec une connexion séparée, probablement dans un processus séparé, tandis que SQLITE_L BOCKED indique un conflit dans la même connexion de base de données (ou parfois une connexion de base de données avec un cache partagé).
